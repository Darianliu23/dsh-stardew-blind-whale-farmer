# dsh-stardew-blind-whale-farmer

在 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)（DSH）里调整 **大肥鱼种白饭 Blind Whale Farmer** 星露谷模组。

**设置在哪**：DSH 左侧边栏「插件」→ dsh-stardew-blind-whale-farmer → 点组件名旁边的「配置 ›」，打开后按「游玩 / 攻略 / 会话与连接 / 模组安装」分组，改完点「保存」，十几秒内推到游戏。装好或升级插件后要重启一次 DSH，配置入口才会出现。（DSH 不会照着插件的配置结构自动画表单，这个配置卡片是插件自带的 `lib/client.js`。）

## 安装和更新

插件包里带着编译好的模组（`release/BlindWhaleFarmer`）。从插件市场装好后，插件会自动把模组装进游戏的 `Mods`；以后插件市场提示有新版本时点“更新”，插件和模组一起更新（模组在游戏关着时装，开着就等关了再装）。

插件和模组用**同一个版本号**（从 1.1.4 起）：插件市场靠仓库 `package.json` 的 `version` 判断有没有新版本，所以每次发版两边一起改。

## 只在选中的会话里玩

DSH 的会话可以选“预设”（agent preset），每个预设带一套自己的插件。在设置里打开开关后，这个插件会注册一个 **“大肥鱼种白饭”预设 = 基础预设（默认 `standard`）的全部插件 + 连游戏的 MCP 客户端**：

- 新建会话时选“大肥鱼种白饭”，这个会话才会连上游戏、拿到 `get_state` 等工具和游戏说明；
- 其他会话（普通聊天、写代码……）里**完全没有**星露谷的工具和说明，不占它们的上下文；
- 每次 DSH 启动都从基础预设现读一遍，DSH 升级 `standard` 时自动跟着变；
- 预设的改动只影响之后新建的会话，已经开着的会话不变。
- **已经对话过的会话用不了**：DSH 规定会话开始聊天后就不能再换预设（源码里会报 `agent-preset/locked`），所以要玩请新建一个会话，在发第一条消息前选这个预设。游戏进度在存档里，AI 用 `update_notes` 写的长期笔记也会出现在每次 `get_state` 的最前面，新会话能接着上次的计划玩。

所以**不要**再在 profile 的 `cordis.patch.yml` 里全局挂 `@deepseek-ai/dsh-mcp-client` 连星露谷，否则每个会话都会带上这些工具。

## 不换预设也能玩：入口工具

打开“在所有会话里提供 stardew 入口工具”后，**每个会话（包括已经聊过的老会话）**都会多一个工具 `stardew`：

- 常驻上下文里只有这一个工具的简短说明（一两百 token），不会把四十多个游戏工具和长说明塞进每个会话；
- AI 要玩时先调 `{"action":"help"}`，拿到操作规则和全部动作的精简列表；攻略用 `{"action":"get_guide"}` 按需读；
- 之后每个动作都是 `{"action":"动作名","args":{参数}}`，例如 `{"action":"move_to","args":{"x":64,"y":15}}`，插件把它转发给游戏里的 MCP 服务器；
- 游戏没开时会直接告诉 AI“连不上游戏”，不会卡住。

和预设比：预设里每个动作是独立的工具、参数检查更严格、规则一开始就在上下文里，专门开会话玩体验更好；入口工具胜在随时随地。两个开关可以同时打开。

## 模型回复坏了自动续玩

模型偶尔会把工具调用吐成一串坏掉的文字（比如 `</｜｜DSML｜｜ invoke>`），服务商没把它解析成工具调用，DSH 就以为模型说完了，这一轮停下，游戏也跟着暂停。2026-11-01 的一次长会话里，816 条回复中出现过 2 次。

开启后插件会盯着会话事件：**这一轮调用过星露谷工具、最后一条回复是这种坏掉的工具调用、这一轮正常结束**，就等会话空闲后自动发一句“接着玩”（和 DSH 自己的目标续跑一样用 `agent.followup`）。

- 只认这一种坏回复：模型正常说完、出错、被你打断时都不会发；
- 不玩游戏的会话不受影响；你已经自己发了消息时也不插嘴；
- 连续自动续玩超过上限、中间没有一次游戏动作成功，就不再续，免得模型一直坏掉时无限循环。

### 说了“玩半小时”“玩 4 个游戏日”就玩够

跟她说“玩半小时”“玩一个小时”时，她会先用 `play_for` 记下分钟数（现实时间，从这时候算）；说“玩 4 个游戏日”“玩一周”时记下游戏日数（今天算第 1 天，睡醒一次算过了一天，读档不算）。之后每个动作结果后面都写着还剩多少，读状态时最前面也有。她要是做完一件事、或者睡了一觉就停下来汇报了，而还没玩够，插件会等会话空闲后自动发一句“接着玩”（同一个开关、同一个次数上限）。玩够了她会收尾汇报；跟她说“不玩了”她会传 0 取消。按停止、自己发了消息时都不会续。

这个时长和上面“每次玩多少分钟/天”不是一回事：那个是**最多**玩多久，到了就让她回家睡觉；这个是玩家这一次要她**玩够**多久。两个都设了时，先到上限就按上限停。

### 保持唤醒（说完自动接着玩）

默认开启“保持唤醒”后，在玩星露谷的会话里，只要 AI 这一轮调用过游戏工具且正常结束（`completed`），插件就会在会话空闲后自动发一句“继续玩，按自己的计划做下一件事”，**不限于睡觉之后**，避免 AI 一轮说完或写完总结就停下等玩家。

- **什么时候停**：达到玩家设置的游玩上限（`每次玩几个游戏日` 默认 **3 天**、`每次玩多少分钟` 默认 **60 分钟**，先到哪个先停）、玩家接管、内置 AI 运行中、游戏未连接、回合被玩家打断/取消、玩家已自己发了消息，或者连续 `autoContinueMax` 次续玩都没有成功的游戏动作时停下。
- **费用提醒**：如果把“每次玩几个游戏日”和“每次玩多少分钟”都改成 **0（不限）**，AI 会一直玩下去，持续消耗 API 额度。
- **和“睡醒自动续玩天数”的关系**：开启“保持唤醒”时，“睡醒自动续玩天数”不起作用（停不停按总游玩上限来）；有 `play_for` 目标时仍然优先按 `play_for` 续玩。

### 关闭“保持唤醒”时：睡醒自动续玩下一天

如果关掉“保持唤醒”，就恢复原有行为：只在回复坏掉、`play_for` 未玩够，或睡醒进入新的一天时续玩。此时“睡醒自动续玩天数”（默认 **3 天**，可在 0–30 之间调，0 为关闭，受“自动续玩”总开关控制）生效：只要这一轮确实睡过觉进入（或正在进入）新的一天，且不在玩家接管中、没到 `每次玩几个游戏日 / 多少分钟` 上限，插件会在空闲后自动发一句“接着玩”，最多连续指定天数后停下等玩家。玩家自己发一条消息后计数清零；想连续玩更久可以直接跟她说“玩 N 天”。

## 怎么起作用

模组在游戏里开了一个只监听本机的服务（和 MCP 同一个端口），`/settings` 接收设置，`/thought` 接收 AI 的思考和说话文字并显示在左上角 HUD。
这个插件每 15 秒问一次游戏“现在用的是哪一版设置”，不一样就推过去：

- 改了设置，十几秒内生效，不用重启游戏和 DSH；
- 游戏没开时什么也不做，开了以后自动补推；
- 模组会把设置写回自己的 `config.json`，不开 DSH 时也照样有效。

## 安装

DSH 的桌面版和网页版用的是不同的 profile（`<DSH_HOME>/profiles/desktop` 和 `profiles/web`），**每个要用的 profile 都要装一次**。

**从 GitHub 装**：插件就在仓库根目录，在 DSH 的插件页面用 `github:Darianliu23/dsh-stardew-blind-whale-farmer` 安装即可（只会装 `lib/`、`cordis.patch.yml` 等几个文件，不会把模组源码装进 DSH）。

**从本地文件夹装（开发时）**：在 profile 目录里

1. `package.json` 的 `dependencies` 加 `"dsh-stardew-blind-whale-farmer": "link:<本仓库路径>"`，`dsh.profile.bundles` 里加 `"dsh-stardew-blind-whale-farmer"`；
2. 在 profile 目录运行 `pnpm install`，然后重启 DSH。

注意用和这个 profile 一致的 pnpm（看 `node_modules/.modules.yaml` 里的 `packageManager`）：桌面版的 profile 是 DSH 桌面版自带的
pnpm 11 建的（在 `DeepSeek Harness/resources/runtime/primary-runtime/dependencies/pnpm`），用别的大版本 pnpm 会要求重建整个 `node_modules`。

配置结构需要 `@deepseek-ai/schemastery`。用 link 装时插件会到 `DSH_HOME` 的 profile 目录和 DSH 程序目录里去找；
实在找不到也不会加载失败，只是配置卡片读不到设置，插件按默认值工作。

改了 `lib/index.js` 的 `Config`（加减设置项）以后运行 `npm run build:client` 重新生成配置卡片 `lib/client.js`，测试会检查它是不是最新的。
